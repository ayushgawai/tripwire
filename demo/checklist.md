# Checks before recording

Run all eight against a running backend (`uvicorn backend.app:app`, `http://localhost:8000`).
Event names are from `shared/COORDINATOR.md`. `demo/smoke.py` automates 1, 2, 3, 6, 8; the rest
are live, headphone-based checks. All three takes must pass before the 90-second recording.

| | Check | How to run it | Expected events | Pass / fail | Notes |
| --- | --- | --- | --- | --- | --- |
| - [ ] | 1. Benign call | `demo/smoke.py` scenario 1, or presenter UI: fresh session, post "Please call me back tomorrow." | `transcript.final`, `risk.updated` (risk `low`, action `none`); state stays `monitoring`; **no** `takeover.started`, no `family.alert` | ☐ P / ☐ F | Any takeover here = detector false positive |
| - [ ] | 2. Ambiguous charge | `demo/smoke.py` scenario 2: post "The service costs $2,000." | `risk.updated` with risk at most `review` (a large price alone is not proof of a scam); **no** `takeover.started`; state stays `monitoring` | ☐ P / ☐ F | `review` + action `alert` may publish `family.alert`; that is fine — the bar is "no takeover" |
| - [ ] | 3. Scam script | `demo/smoke.py` scenario 3 with the plan lines: "Grandma, I am in trouble. Buy $500 in gift cards now. Please do not tell anyone." / "Should I call your mother?" / "No. There is no time." | `transcript.final` ×3, `risk.updated` (risk `high`, evidence quotes + `takeover.started`), **exactly one** `takeover.started`, **exactly one** `family.alert` (stored once on the session); `takeover.active` only after `wearer_audio_blocked` + assistant ready; state `monitoring → protecting` | ☐ P / ☐ F | Duplicates must not add a second `takeover.started`/`family.alert` (covered by check 6) |
| - [ ] | 4. Wearer truly cannot hear caller | Live call, headphones on: start the scam flow, confirm on the wearer laptop's audio output what happens at takeover; caller + AI still exchange lines | After `takeover.started`: snapshot `wearer_connected=false`; wearer track silent to caller while caller still hears AI; no new event expected when `takeover.active` lands | ☐ P / ☐ F | If the caller is still audible to the wearer, the takeover failed — stop, do not continue the take |
| - [ ] | 5. Daughter alert + join + reconnect | Daughter on family page during a live scam flow; press Join; then press "Reconnect wearer" | `family.alert` (with quoted evidence) → `family.joined {participant}`, state `assistant_active → family_joined`, AI stops speaking; `wearer.reconnected` **only** after the explicit `wearer_reconnect` signal (state `family_joined`) | ☐ P / ☐ F | Verify the join against the real provider participant-joined event, not a button click |
| - [ ] | 6. Duplicates are no-ops | `demo/smoke.py`: re-post a duplicate `utterance_id` after the scam takeover; then refresh the family page | Duplicate post returns `{accepted: true, duplicate: true}`; no new `takeover.started`/`family.alert`; snapshot `last_sequence` unchanged, `alert` unchanged; refresh restores current state via GET snapshot | ☐ P / ☐ F | Idempotent `begin_takeover` — duplicate high decisions do nothing |
| - [ ] | 7. Failure is visible | Force one: kill the voice worker (or strip a provider credential) mid-takeover | `takeover.failed {reason}` (e.g. `timeout`, `calls module unavailable`) or `error {source: "intelligence"}`; state stays `protecting`; UI offers End call | ☐ P / ☐ F | Never show a successful takeover on button click alone |
| - [ ] | 8. Clean end + repeat | `demo/smoke.py` end assertions, then live: POST `/end`; then start a brand-new session and repeat the full demo | `session.ended`; audio capture and worker shut down; **any** further call on the old session → 410; new session starts at `monitoring` cleanly; complete demo repeats **3 times** | ☐ P / ☐ F | Repeat the whole demo three times before recording |
